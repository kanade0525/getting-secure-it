# Getting Secure It

自作のECサイトを公開した店長が、攻撃を受けながら少しずつ守りを固めていく Webセキュリティ学習シミュレーションゲーム。

全4章・24日（通信編 0〜3日目／アプリ編 4〜11日目／防壁編 12〜17日目／運用編 18〜24日目）。

## 対策を入れる場所

対策は、それが実際にある場所で入れます。お店のコードを直すのはピクセルハブだけで、設備の設定はピクセルクラウドやネームヤの管理画面で変えます。

| サービス | たとえると | ここで入れる対策 |
| --- | --- | --- |
| ネームヤ | ドメイン会社 | ドメインの取得・DNS（0・1・12日目）、移管ロックと2段階認証（23日目） |
| ピクセルクラウド | AWS のようなクラウド | 証明書・通信設定（1〜3・18・21日目）、入口（CDN）・WAF（12〜16日目）、ファイアウォール（17・24日目）、サーバーの更新（19日目）、シークレット（22日目）、監視（24日目） |
| 認証局 | 証明書の発行元 | 証明書の発行（1日目） |
| ピクセルハブ | GitHub のようなコード置き場 | コードの修正をプルリクエストでマージする（4〜11・15・20・22日目）。入れた修正はコミット履歴に残る |

WAF のレート制限のような値は、管理画面で選び直せます。ゆるすぎると防げず、きつすぎるとお客さんを困らせます（どちらもクリアにならず、エンドロールの「引っかかったトラップ」に残ります）。

## 1日の流れ

朝の会話 → お知らせが届く →「お知らせ」タブで読む →「通信」タブで何が起きているか見る →「管理」タブで対策 → 右下の「防げたか確かめる」→ 解説。
「お知らせ」を読む前に「通信」を開いても、再生は始まりません。24日目をクリアすると、エンディングとエンドロールが流れます。

## ファイル

| ファイル | 中身 |
| --- | --- |
| `index.html` | 画面・CSS・ゲームエンジン |
| `days.js` `days-ch2.js` `days-ch3.js` `days-ch4.js` | ステージ定義（セリフ、判定、解説、対策を入れる場所）。章ごとに1ファイル。項目の意味は `days.js` の冒頭 |
| `sprites.js` | 24色パレットと16×16のキャラ、UIアイコン |
| `art/gsi.px.js` | 追加素材の元データ（pxl 形式） |
| `art/gsi-net.px.js` | 通信図の素材の元データ（機器・パケット・盾など） |
| `art/gsi-title.px.js` | タイトルのジオラマ（アイソメ）・お店のアイコン・ファビコンの元データ |
| `title.png` `favicon.png` `apple-touch-icon.png` | 上の元データから作った画像（下の手順で作り直す） |

## 絵を作り直す

タイトルの絵とファビコンは、pxl でビルドしてリポジトリ直下に置きます。

```sh
node ~/.claude/skills/pxl-pixel-art/bin/pxl.js build art/gsi-title.px.js
cp art/out/scenes/title.png title.png
cp art/out/sprites/favicon.png favicon.png
cp art/out/sprites/touch.png apple-touch-icon.png
```

お店のアイコン（`shop16`）を変えたら、`sprites.js` の `icons.shop` にも同じ行データを写します。

## ローカルで動かす

ビルド不要。`index.html` をブラウザで開くだけで動きます。

## 日を選ぶ・デバッグ

- タイトルの「日を選ぶ」か、画面上部の日付を押すと、日の一覧が開きます。クリアした日と、その次の日を選べます。選んだ日の朝の設定（前の日までの対策が入った状態）から始まります。
- デバッグ：URL の末尾に `#debug` を付けて開くか、タイトルの「全4章・24日…」を続けて5回押すと、どの日でも選べます。「対策の場面から始める」にチェックを入れると、朝の会話と攻撃の再生を飛ばします。一覧の最後から、エンディングとエンドロールも見られます（一般のプレイヤーは、全部クリアしたあと）。
- 日を足したり並べ替えたりしたら、`index.html` の保存データの版（`rev`）と読み込み時の引き継ぎ方を合わせます。選んだ日の朝の設定は、各日の `fix`（コードの修正）と `solve(c)`（管理画面の設定の正解）から作るので、日を足したらこの2つを書きます。

## テスト

Playwright で実際に操作して確かめます（CI では走りません。手元で、変えた所に関係するものだけ）。

```sh
node test/smoke.cjs       <フォルダ または URL> <スクショの出力先>            # 0〜3日目を最初から通す
node test/smoke-infra.cjs <フォルダ または URL> <スクショの出力先> [開始日]   # 12〜24日目とエンディングを、画面の操作だけで通す（トラップも踏む）
node test/smoke-net.cjs   <フォルダ または URL> <スクショの出力先> [日,日,…]  # 通信タブ：全24日
node test/smoke-site.cjs  <フォルダ または URL> <スクショの出力先> [日,日,…]  # サイトタブ・管理タブのデモ
node test/smoke-days.cjs  <フォルダ または URL> <スクショの出力先>            # 日を選ぶ・デバッグ・古い保存データの引き継ぎ
```
